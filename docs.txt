===================================

This document describes the reusable Python modules created for FPL analysis and optimization.

================

fpl_analyzer.py
===============

Main analysis module providing comprehensive FPL data analysis capabilities.

CLASSES
-------

FPLAnalyzer
-----------
Main analysis class for FPL data processing and optimization.

Constructor:
  FPLAnalyzer(data_dir="data")
  - data_dir: Directory containing CSV files

Methods:

  load_data()
  - Loads all CSV files into memory
  - Must be called before other methods
  - Populates: players, teams, fixtures, gameweeks, team_picks, team_history, player_stats

  get_current_gameweek() -> int
  - Returns current gameweek number
  - Uses is_current flag from gameweeks data

  get_next_gameweek() -> int  
  - Returns next gameweek for planning purposes
  - current_gw + 1 or current_gw if season ended

  get_current_squad() -> pd.DataFrame
  - Returns current team selection with player details
  - Includes player names, costs, points, form, team info
  - Sorted by position and squad position

  analyze_squad_value() -> Dict
  - Returns squad financial analysis
  - Keys: squad_value, bank, total_value, player_count
  - All values in millions (£)

  get_upcoming_fixtures(team_id, gameweeks=5) -> pd.DataFrame
  - Returns upcoming fixtures for specified team
  - gameweeks: Number of gameweeks to look ahead
  - Includes opponent, home/away, kickoff times

  calculate_fixture_difficulty(team_id, gameweeks=5) -> float
  - Calculates average fixture difficulty (1-5 scale)
  - Based on opponent strength ratings
  - 1 = easiest, 5 = hardest

  get_form_analysis(player_id, gameweeks=5) -> Dict
  - Analyzes player form over recent gameweeks
  - Returns: points list, avg_points, games played, total minutes

  identify_transfer_targets(position, max_cost, min_form=5.0) -> pd.DataFrame
  - Finds potential transfer targets by position
  - position: 1=GK, 2=DEF, 3=MID, 4=FWD
  - max_cost: Maximum cost in millions
  - min_form: Minimum form rating
  - Returns sorted by form and value score

  get_transfer_recommendations(max_transfers=2) -> Dict
  - Generates transfer recommendations for problem players
  - Identifies players with form < 2.0 or injury/suspension status
  - Returns structured data with transfer options and costs
  - Keys: recommendations, problem_count, bank_balance, total_cost
  
  print_transfer_recommendations(max_transfers=2)
  - Prints formatted transfer recommendations
  - Shows priority transfers with cost analysis and form improvements
  - Includes budget warnings if transfers exceed available funds
  - Shows instructions for executing transfers
  
  execute_transfers(email, password, max_transfers=2) -> Dict
  - Automatically execute recommended transfers
  - Requires FPL login credentials
  - Uses fpl_session module for authenticated requests
  - Returns transfer result or None if failed
  
  print_squad_summary()
  - Prints formatted current squad analysis
  - Shows all players by position with key stats
  - Includes financial summary

CONVENIENCE FUNCTIONS
--------------------

quick_analysis() -> FPLAnalyzer
- Quick way to load data and print squad summary
- Returns analyzer instance for further analysis

get_recommendations(max_transfers=2) -> FPLAnalyzer
- Quick transfer recommendations for problem players
- Identifies and suggests replacements for low form/injured players
- Shows cost analysis and form improvements
- Returns analyzer instance for further analysis

execute_recommended_transfers(max_transfers=2) -> Dict
- Quick analysis and transfer execution using stored credentials
- Combines get_recommendations() and execute_transfers()
- Requires credentials to be set up first with setup_credentials.py
- Returns transfer result or None if failed

find_transfers(position, max_cost, min_form=5.0) -> pd.DataFrame
- Quick transfer target finder
- position: 'GK', 'DEF', 'MID', 'FWD'
- Prints top 10 targets and returns full dataframe

USAGE EXAMPLES
==============

Basic Analysis:
```python
from fpl_analyzer import quick_analysis
analyzer = quick_analysis()
```

Transfer Target Search:
```python
from fpl_analyzer import find_transfers
targets = find_transfers('MID', 8.0, 6.0)  # Midfielders under £8m with 6+ form
```

Advanced Analysis:
```python
from fpl_analyzer import FPLAnalyzer

analyzer = FPLAnalyzer()
analyzer.load_data()

# Current squad
squad = analyzer.get_current_squad()

# Fixture analysis
fixtures = analyzer.get_upcoming_fixtures(1, 3)  # Arsenal next 3 games
difficulty = analyzer.calculate_fixture_difficulty(1, 5)  # Arsenal next 5 games

# Player form

# Transfer targets

```

COMMON WORKFLOWS
===============

1. SQUAD REVIEW:
   - quick_analysis() for overview
   - Check player status (injuries/suspensions)
   - Analyze upcoming fixtures for each player

2. TRANSFER PLANNING:
   - find_transfers() for each position of interest
   - Compare fixture difficulty of current vs target players
   - Check form trends using get_form_analysis()

3. CAPTAIN SELECTION:
   - Get current squad with get_current_squad()
   - Analyze fixtures for next gameweek
   - Check recent form for premium players

4. CHIP TIMING:
   - Analyze fixture difficulty across multiple gameweeks
   - Look for favorable fixture runs for bench boost
   - Identify double gameweeks for wildcard timing

DATA REFRESH
============

Before each analysis session:
1. Use MCP server: download_latest_data()
2. Load fresh data with analyzer.load_data()
3. Proceed with analysis

This ensures all analysis uses the most current FPL data including:
- Latest player prices and form
- Recent injury/suspension updates  
- Updated fixture schedules
- Current gameweek status

fpl_actions.py
==============

Authenticated actions against a real FPL team: logging in, saving the starting
XI, and making transfers. Replaces the removed fpl_session.py and
credentials_manager.py.

The read-only public API needs no auth; everything here does. Three ways to
get a session, all returning a session dict:

  get_session()                              -> cached session, re-login if stale
  login(email, password, headless=True)      -> drives a browser (Playwright)
  session_from_token(access_token)           -> a token copied from a browser

get_session() is the one to call from analysis scripts: it reuses the saved
session, checks it still works, and logs in again only when it does not. That
makes scheduled/headless runs hands-off, provided .credentials holds a working
email and password.

AUTH IS A BEARER TOKEN, NOT COOKIES  (verified against the live API)
--------------------------------------------------------------------
  X-Api-Authorization: Bearer <access_token>

Measured, not assumed:
  - token, no cookies at all          -> 200
  - every cookie the site sets, no token -> 403 "credentials were not provided"
  - id_token instead of access_token  -> 401 "Audience doesn't match"

So cookies are not collected or sent at all. Only two headers matter on a
write: the bearer token and Content-Type: application/json. Specifically:
  - Referer is NOT checked - a deliberately wrong one still returns 200
  - X-CSRFToken is ignored - a bogus value still returns 200. There is no
    cookie session for CSRF to protect, so no token is involved
  - omitting Content-Type gives 415, not 403
We still send Referer and X-Requested-With to look like the site's own
client, but nothing depends on them.

LOGIN FLOW (changed - myPL migration)
-------------------------------------
The old users.premierleague.com login was retired; the host does not resolve
at all any more. Logging in now means the myPL OAuth flow:

  fantasy.premierleague.com/my-team
    -> click "Log in"
    -> account.premierleague.com/as/authorize   (PingOne, PKCE)
    -> form: #username, #password, #btnSignIn
    -> redirect back to fantasy.premierleague.com with an auth code
    -> the site exchanges it for tokens, kept in localStorage under
       "oidc.user:https://account.premierleague.com/as:<client id>"

login() drives exactly that and reads access_token out of that entry. It
clicks the site's own "Log in" button rather than building an authorize URL
by hand, because the URL carries a PKCE challenge and state that the app
generates. The page serves no captcha to a scripted browser, so headless
works.

Tokens last about an hour (expires_at in the session dict). get_session()
notices and logs in again, which takes ~20 seconds. The refresh_token is
saved but not used: POSTing it to as/token.oauth2 returns 403 "Missing
Authentication Token", so a fresh login is the working path.

CREDENTIAL FILES
----------------
  .credentials          {"username": ..., "password": ...}, written by you
  .session.credentials  saved token, written by save_session()

These are deliberately separate files: save_cookies() used to write over
.credentials, destroying the stored email and password. Both are gitignored.

SAFETY
------
Every mutating method takes confirm=False by default. In that mode it prints
the exact JSON it would POST and returns it without contacting FPL. Pass
confirm=True only once the payload looks right.

CLASSES
-------

FPLTeam
-------
Async context manager wrapping an authenticated aiohttp session.

Constructor:
  FPLTeam(session, team_id=TEAM_ID)
  - session: dict from get_session(), login() or session_from_token().
    A bare token string is accepted too
  - team_id: FPL entry id, defaults to constants.TEAM_ID (3593814)

Methods:

  get_my_team() -> dict
  - Keys: picks, chips, transfers, picks_last_updated
  - Each pick carries element, element_type, position, multiplier,
    is_captain, is_vice_captain, selling_price, purchase_price
  - transfers: {cost, status, limit, made, bank, value}. Pre-season, status
    is "unlimited" and limit is null
  - Raises a clear error on 401/403 (token missing or expired) and on 404
    (entry does not exist, or is not managed by this account)

  is_logged_in() -> bool
  - Asks for the squad and reports whether it worked. The only reliable test
    of a session, now that cookie names are not stable

  get_current_gameweek() -> int
  - The next gameweek to be played (is_next), falling back to is_current

  set_lineup(picks, chip=None, confirm=False) -> dict
  - Saves starting XI, bench order, captain and vice-captain
  - chip: "bench_boost" or "triple_captain"
  - picks come from build_picks()

  make_transfers(transfers, gameweek=None, chip=None, confirm=False) -> dict
  - chip: "wildcard" or "free_hit" to make the transfers free
  - transfers come from plan_transfers()

  plan_transfers(moves, players_by_id) -> list
  - Turns [(element_out, element_in), ...] into a priced transfers list
  - Reads selling_price from the live squad, which is the only place the
    50% sell-on fee is accounted for. Do not use now_cost to sell.

FUNCTIONS
---------

  build_picks(starting_xi, bench, captain, vice_captain) -> list
  - starting_xi: 11 ids, goalkeeper first
  - bench: 4 ids in substitution priority, reserve goalkeeper first
  - Assigns positions 1-11 to the XI and 12-15 to the bench

  validate_lineup(picks, players_by_id) -> list
  - Returns a list of human-readable problems; empty means legal
  - Checks squad size, position numbering, 1 GK / 3-5 DEF / 1-3 FWD in the
    XI, reserve keeper at position 12, and captain/vice validity
  - Run this before set_lineup() to catch errors without a round trip

  save_session(session) / load_session()
  - Persist to .session.credentials (gitignored, chmod 600)
  - A session saved by an older version (cookies) is ignored, not fatal

  load_credentials() -> (username, password)
  - Reads .credentials, returning (None, None) if absent or unreadable

  get_session(team_id=TEAM_ID, force_login=False) -> dict
  - Cached token if it still works, otherwise a fresh headless login

  session_from_token(access_token) -> dict
  - For when a browser cannot be launched. Find the token in DevTools >
    Application > Local Storage under the oidc.user:... key

RUNNING ON A MACHINE WITHOUT ROOT (Linux)
------------------------------------------
Playwright's Chromium needs ~70 Ubuntu packages (libatk, GTK, fontconfig...)
that `playwright install-deps` installs with sudo. Without sudo, get the same
libraries unprivileged and the module finds them by itself:

  .venv/bin/python -m playwright install chromium
  .venv/bin/python -m playwright install-deps chromium --dry-run \
      | grep -E '^\s+\S' | awk '{print $1}' > .chromium-libs/pkgs.txt
  (cd .chromium-libs/debs && apt-get download $(cat ../pkgs.txt))
  for d in .chromium-libs/debs/*.deb; do dpkg -x "$d" .chromium-libs/root; done

_browser_env() detects .chromium-libs/root, builds LD_LIBRARY_PATH from every
directory under it that holds a .so, and sets FONTCONFIG_PATH, then passes that
env to chromium.launch(). The directory is gitignored (~300MB) and is a no-op
where the system packages exist.

This repo on Linux uses a venv: run everything with .venv/bin/python, not
python3 (system Python is PEP 668 externally managed).

Login failure reporting reads document.body.textContent, not innerText:
innerText needs a computed layout and comes back empty in headless Chromium,
which hid the site's "invalid username and/or password" banner. login()
polls for either the redirect or that banner, so a bad password fails in
~10s with the reason rather than after the full timeout with none.

USAGE EXAMPLES
--------------

Establish a session:

  python3 fpl_actions.py                  # reuse saved session, re-login if stale
  python3 fpl_actions.py --login          # force a fresh login from .credentials
  python3 fpl_actions.py --login --show-browser        # watch it happen
  python3 fpl_actions.py --token "eyJhbGciOi..."       # token from a browser

Set a lineup:

  import asyncio, pandas as pd
  from fpl_actions import FPLTeam, load_cookies, build_picks, validate_lineup

  players = pd.read_csv("data/players.csv").set_index("id")
  players_by_id = players.to_dict("index")

  picks = build_picks(
      starting_xi=[...11 ids, GK first...],
      bench=[...4 ids, reserve GK first...],
      captain=..., vice_captain=...)

  errors = validate_lineup(picks, players_by_id)
  assert not errors, errors

  async def main():
      async with FPLTeam(await get_session()) as team:
          await team.set_lineup(picks)                  # dry run, prints JSON
          await team.set_lineup(picks, confirm=True)    # actually saves
  asyncio.run(main())

Make transfers:

  async def main():
      async with FPLTeam(await get_session()) as team:
          moves = [(out_id, in_id)]
          transfers = await team.plan_transfers(moves, players_by_id)
          await team.make_transfers(transfers)                 # dry run
          await team.make_transfers(transfers, confirm=True)   # applies
  asyncio.run(main())

fpl_report.py
=============

Renders a gameweek report as a single self-contained HTML file - no external
fonts, scripts or images, so it works on GitHub Pages, from disk, or behind a
strict CSP. Around 28KB output.

  from fpl_report import Report, Player, Transfer, Chip, Section, render
  open("docs/gw1.html", "w").write(render(report))

DATACLASSES
-----------
  Player(name, team, pos, price, proj, opponent, difficulty, note,
         is_captain, is_vice)
  - pos is "GKP"/"DEF"/"MID"/"FWD"; team is the three-letter short_name,
    which also selects the shirt colours
  - difficulty 2-5 drives the colour chip next to the fixture

  Transfer(out, into, reason)      - two Players and a one-line rationale
  Chip(name, half, status, detail) - status "AVAILABLE"/"USED"/"LOCKED"
  Section(title, body, tone)       - prose block; blank lines split
                                     paragraphs; tone "default" or "warn"

  Report(gameweek, entry_name, entry_id, deadline, squad_value, bank,
         transfer_status, xi, bench, transfers, chips, chip_decision,
         captain_note, sections, caveats, projected_points, generated,
         persona_body, persona_hint)
  - persona_body: the guest-manager overview for the Team sheet tab, written
    in character. persona_hint is the byline, e.g. "Guest manager: <name>".
    The piece is written in character; the byline is the only framing

  GUEST_MANAGERS / persona_for(gameweek)
  - A fixed rotation of ten voices for the Team sheet verdict, each with a
    note on how it reads on the page. persona_for() picks by gameweek, so the
    schedule can be stated in advance and re-running an old gameweek
    reproduces the same guest
  - Chosen for voices that are unmistakable in writing alone. Fictional
    characters are mixed in with real people deliberately

FUNCTIONS
---------
  render(report) -> str
  - The whole page. Sections with no data are omitted rather than rendered
    empty, so a report with no transfers simply has no transfers section

NOTES
-----
- The bench list must be in payload order: reserve goalkeeper first (squad
  position 12), then outfield subs 13-15. render() pulls the keeper into its
  own slot, since it can only replace the starting keeper and is not part of
  the outfield substitution priority
- The formation string is derived from the XI, not passed in
- Kits live in KITS as (primary, secondary, pattern) where pattern is
  "solid", "stripes" or "sleeves". Stripes and contrast sleeves are drawn as
  rects clipped to a shared shirt silhouette. Add promoted clubs each season
  and check the pattern, not just the colour - a striped club rendered flat
  is immediately obvious to anyone who watches football
- Committed to a dark theme deliberately - it does not follow the viewer's
  light/dark preference
- Mobile layout has media queries but has not been verified in a real
  narrow viewport
- Two tabs, switched with CSS only (radio inputs plus :checked siblings), so
  no script is needed: "Full report" is the long form, "Team sheet" is a
  compressed side-by-side of the XI and the verdict, sized to fit a single
  screenshot (about 730px tall at desktop width)
- Tabs are deep-linkable: gw1.html#sheet opens the Team sheet, #report the
  long form. A small inline script syncs the hash; without script the tabs
  still work, they just cannot be linked to

fpl_projection.py
=================

Per-gameweek points projections.

THE TRAP THIS EXISTS TO AVOID
-----------------------------
bootstrap-static resets total_points, starts and minutes at the season
rollover. Any model reading those fields silently degrades to noise in GW1
and stays there for weeks - every player collapses to the same price-implied
prior and the rankings become meaningless. This was live in the GW1 model and
was only caught when GW2 projections came back flat at ~1.0 across the board.

Last season's record survives only in each player's element-summary, under
history_past. Cache it once per season.

  Projector(bootstrap, fixtures, history_past)
    .project(element, gameweek) -> dict or None
    .horizon(element, first, last) -> float
    .fixture(team_id, gameweek) -> (opponent, difficulty, is_home)
    .availability(element) -> (multiplier, flag)

HOW A PROJECTION IS BUILT
-------------------------
points per 90 x reliability x fixture multiplier x home/away x availability

  - last season's rate needs 450+ minutes to be trusted at all
  - this season's rate is blended in as minutes accumulate
  - players with NO Premier League record (promoted clubs, overseas signings)
    are shrunk toward a price-implied prior. Without this a newcomer with one
    good match reads as a superstar: 14 points in 75 minutes scales to 16.8
    per 90. Shrinkage weight is mins/(mins+540)
  - defenders and keepers get a harder fixture swing than attackers, since
